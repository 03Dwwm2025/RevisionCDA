## Le référentiel CDA en bref

La certification CDA (titre professionnel de niveau 6, équivalent bac+3/4) est organisée en trois blocs de compétences (CCP) qui correspondent exactement aux trois parties de ce cours.

| Bloc (CCP) | Intitulé | Ce qu'on y fait |
| --- | --- | --- |
| CCP 1 | Développer une application sécurisée | Environnement de dev, interfaces utilisateur, composants métier, gestion de projet |
| CCP 2 | Concevoir et développer une application sécurisée organisée en couches | Analyse des besoins, maquettage, architecture, modélisation et accès aux données |
| CCP 3 | Préparer le déploiement d'une application sécurisée | Tests et recette, conteneurisation, CI/CD, mise en production, supervision |

---

### Les compétences, une par une

C'est la grille sur laquelle le jury raisonne. Chaque compétence est rattachée à un chapitre de ce cours.

**CCP 1 — Développer une application sécurisée**

| Compétence | Chapitres |
| --- | --- |
| Installer et configurer son environnement de travail | L'environnement de développement |
| Développer des interfaces utilisateur | Maquettage, Front-end |
| Développer des composants métier | POO, SOLID, Architecture en couches, Back-end |
| Contribuer à la gestion d'un projet informatique | Cycle de vie, Analyse des besoins, Git |

**CCP 2 — Concevoir et développer une application sécurisée organisée en couches**

| Compétence | Chapitres |
| --- | --- |
| Analyser les besoins et maquetter une application | Analyse des besoins, UML, Maquettage |
| Définir l'architecture logicielle | Architecture logicielle, Architecture en couches |
| Concevoir et mettre en place une base de données relationnelle | Modélisation des données, Bases de données et SQL |
| Développer des composants d'accès aux données SQL et NoSQL | Bases de données et SQL, API REST |

**CCP 3 — Préparer le déploiement d'une application sécurisée**

| Compétence | Chapitres |
| --- | --- |
| Préparer et exécuter les plans de tests | Tests |
| Préparer et documenter le déploiement | Docker, Mise en production |
| Contribuer à la mise en production dans une démarche DevOps | CI/CD, Mise en production, Supervision |

### Comment se passe l'examen

| Épreuve | Ce qu'on attend |
| --- | --- |
| **Dossier de projet** | Un document rédigé en amont, qui présente un projet réel : contexte, expression des besoins, conception (MCD, UML, maquettes), extraits de code représentatifs, jeu d'essai et plan de tests, éléments de sécurité, veille |
| **Présentation orale** | Une soutenance du projet devant le jury, appuyée sur un support |
| **Entretien technique** | Des questions ciblées sur le dossier et sur les compétences du référentiel — c'est là que le contenu de ce cours sert directement |
| **Questionnaire professionnel** | Des questions écrites sur les compétences, dont la sécurité |
| **Entretien final** | Un échange sur le métier, le parcours et la compréhension du rôle de concepteur développeur |

**Deux conseils qui pèsent plus que les autres :**

1. **Tout ce qui est dans le dossier peut être questionné.** Un diagramme collé sans être compris est une invitation directe à une question à laquelle on ne saura pas répondre. Ce qu'on met, on doit savoir le justifier.
2. **La sécurité est attendue partout**, pas dans un chapitre à part. C'est le fil rouge du référentiel — d'où les encadrés sécurité à la fin de chaque chapitre de ce cours.
